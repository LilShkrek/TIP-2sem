# Практическая работа №11. GraphQL API на Go

## Цель

Освоить разработку учебного GraphQL API на Go с использованием `gqlgen`: описать схему, сгенерировать серверный каркас, реализовать запросы и мутации для сущности `Task`, проверить работу через Playground.

## Задание

Реализовать GraphQL API для задач с полями `id`, `title`, `description`, `done`.

Поддерживаемые операции:

- `tasks` - получить список задач;
- `task(id: ID!)` - получить задачу по идентификатору;
- `createTask(input: CreateTaskInput!)` - создать задачу;
- `updateTask(id: ID!, input: UpdateTaskInput!)` - обновить задачу;
- `deleteTask(id: ID!)` - удалить задачу.

Авторизация в учебной версии не используется. Все запросы и мутации доступны без токена.

## GraphQL-схема

Схема находится в `services/graphql/graph/schema.graphqls`.

```graphql
type Task {
  id: ID!
  title: String!
  description: String
  done: Boolean!
}

type Query {
  tasks: [Task!]!
  task(id: ID!): Task
}

type Mutation {
  createTask(input: CreateTaskInput!): Task!
  updateTask(id: ID!, input: UpdateTaskInput!): Task!
  deleteTask(id: ID!): Boolean!
}
```

## Примеры Query

Получение списка задач:

```graphql
query {
  tasks {
    id
    title
    description
    done
  }
}
```

Получение одной задачи:

```graphql
query GetTask($id: ID!) {
  task(id: $id) {
    id
    title
    description
    done
  }
}
```

Переменные:

```json
{
  "id": "t_001"
}
```

## Примеры Mutation

Создание задачи:

```graphql
mutation Create($input: CreateTaskInput!) {
  createTask(input: $input) {
    id
    title
    description
    done
  }
}
```

Переменные:

```json
{
  "input": {
    "title": "Изучить GraphQL",
    "description": "Реализовать API через gqlgen"
  }
}
```

Обновление задачи:

```graphql
mutation Update($id: ID!, $input: UpdateTaskInput!) {
  updateTask(id: $id, input: $input) {
    id
    title
    description
    done
  }
}
```

Переменные:

```json
{
  "id": "t_001",
  "input": {
    "done": true
  }
}
```

Удаление задачи:

```graphql
mutation Delete($id: ID!) {
  deleteTask(id: $id)
}
```

Переменные:

```json
{
  "id": "t_001"
}
```

## Ответы на контрольные вопросы

1. **Что такое GraphQL и в чём его основное отличие от REST API?**

   GraphQL — это язык запросов к API и подход к построению серверного интерфейса, при котором клиент сам указывает, какие данные и какие поля ему нужны. Главное отличие от REST в том, что в REST обычно есть несколько заранее заданных endpoint-ов, а в GraphQL чаще используется один endpoint, например `/query`, и структура ответа определяется самим запросом клиента.

2. **Для чего используется GraphQL-схема?**

   GraphQL-схема описывает контракт API. В ней указываются доступные типы данных, запросы, мутации и входные параметры. По схеме клиент понимает, какие операции доступны, а сервер — какие резолверы нужно реализовать.

3. **Чем Query отличается от Mutation?**

   `Query` используется для чтения данных, например для получения списка задач или одной задачи по идентификатору.
   `Mutation` используется для изменения данных: создания, обновления или удаления сущностей.

4. **Что такое резолвер и какую роль он выполняет?**

   Резолвер — это функция на стороне сервера, которая выполняет конкретный GraphQL-запрос или мутацию. Например, если клиент вызывает `tasks`, GraphQL-сервер вызывает соответствующий резолвер, а тот обращается к сервисному слою или репозиторию и возвращает результат.

5. **Почему GraphQL позволяет уменьшить over-fetching данных?**

   В GraphQL клиент сам выбирает, какие поля нужно получить. Например, если клиенту нужны только `id` и `title`, он может запросить только эти поля, а не весь объект задачи целиком. Благодаря этому сервер не возвращает лишние данные.

6. **Для чего используется библиотека gqlgen в Go-проекте?**

   `gqlgen` используется для разработки GraphQL API на Go. Она позволяет описать схему в файле `schema.graphqls`, а затем сгенерировать Go-код: модели, интерфейсы и заготовки резолверов. Разработчику остаётся реализовать бизнес-логику в резолверах и сервисном слое.

7. **Почему желательно использовать общий сервисный или репозиторный слой для REST и GraphQL?**

   Общий сервисный или репозиторный слой позволяет не дублировать бизнес-логику в разных API. REST-обработчики и GraphQL-резолверы могут обращаться к одним и тем же методам сервиса. Так проект проще поддерживать, тестировать и расширять.

8. **Что произойдёт, если GraphQL-запрос попытается получить слишком большой объём данных?**

   Такой запрос может создать большую нагрузку на сервер, память и хранилище данных. Если не ограничивать глубину и сложность GraphQL-запросов, клиент может запросить слишком много вложенных данных. В реальных проектах для этого используют ограничения глубины запроса, лимиты, пагинацию и авторизацию.

9. **Какие преимущества даёт Playground при тестировании API?**

   Playground позволяет тестировать GraphQL API прямо из браузера. В нём удобно писать запросы и мутации, передавать переменные, смотреть структуру схемы и проверять ответы сервера без отдельного клиента или Postman.

10. **В каких случаях GraphQL особенно удобен на практике?**

    GraphQL особенно удобен, когда клиентам нужны разные наборы полей из одних и тех же сущностей, когда API используется разными фронтендами или мобильными приложениями, а также когда нужно уменьшить количество отдельных запросов к серверу. Он хорошо подходит для гибких клиентских сценариев, где REST может приводить к over-fetching или under-fetching.
