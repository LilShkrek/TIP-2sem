# Практическое занятие №2

## Цель

Освоить создание простого микросервиса на Go с использованием gRPC: описать контракт в Protocol Buffers, сгенерировать Go-код, запустить gRPC-сервер и выполнить клиентские вызовы.

## Задание

Реализовать учебный сервис `StudentService` с методами:

- `Ping` — проверка доступности сервера;
- `GetStudentByID` — получение данных студента по идентификатору.

Сервис хранит тестовые данные в памяти и слушает порт `50051`.

## Генерация protobuf-кода

Для генерации нужны `protoc`, `protoc-gen-go` и `protoc-gen-go-grpc`.

Установка Go-плагинов:

```bash
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest
```

Генерация из корня проекта:

```bash
protoc --proto_path=proto \
  --go_out=. --go_opt=module=example.com/pz2-grpc \
  --go-grpc_out=. --go-grpc_opt=module=example.com/pz2-grpc \
  proto/student.proto
```

## Запуск сервера

```bash
go run ./cmd/server
```

Ожидаемый вывод:

```text
gRPC server started on :50051
```

## Запуск клиента

Во втором терминале:

```bash
go run ./cmd/client
```

Пример вывода:

```text
Ping response: Server received: hello grpc
Student: id=1, full_name=Иванов Иван Иванович, group=ИВБО-01-25, email=ivanov@example.com
NotFound check: student with id=999 was not found
```

## Проверка ошибки NotFound

Клиент дополнительно вызывает `GetStudentByID` с `id=999`. Такого студента нет в памяти сервера, поэтому сервер возвращает gRPC-ошибку с кодом `NotFound`.

Проверить это можно запуском клиента:

```bash
go run ./cmd/client
```

## Ответы на контрольные вопросы

1. **Что такое gRPC?**

   gRPC — это фреймворк удалённого вызова процедур. Он позволяет одному приложению вызывать методы другого приложения почти как обычные функции, но по сети. В этой работе клиент вызывает методы gRPC-сервера `StudentService`.

2. **Какую роль играет .proto-файл?**

   `.proto`-файл описывает контракт сервиса: какие сообщения существуют, какие поля в них есть и какие методы доступны клиенту. По этому файлу затем генерируется Go-код для сервера и клиента.

3. **Для чего нужен protoc?**

   `protoc` — это компилятор Protocol Buffers. Он читает `.proto`-файл и с помощью специальных плагинов генерирует код для выбранного языка программирования.

4. **Зачем используются protoc-gen-go и protoc-gen-go-grpc?**

   `protoc-gen-go` генерирует Go-структуры для protobuf-сообщений.
   `protoc-gen-go-grpc` генерирует Go-код, связанный с gRPC-сервисом: интерфейсы сервера, регистрацию сервиса и клиент для вызова методов.

5. **Чем gRPC отличается от HTTP JSON API?**

   В HTTP JSON API разработчик обычно вручную описывает URL, JSON-структуры и обработчики. В gRPC сначала описывается строгий контракт в `.proto`, а затем на его основе генерируется типизированный код. Кроме того, gRPC обычно использует protobuf, а не JSON.

6. **Почему контракт в gRPC считается строго типизированным?**

   Потому что все сообщения, поля и методы заранее описаны в `.proto`-файле. Например, если поле `id` имеет тип `int64`, клиент и сервер должны работать именно с этим типом. Это снижает риск ошибок между клиентом и сервером.

7. **Что делает gRPC-клиент в этой работе?**

   gRPC-клиент подключается к серверу на порту `50051` и вызывает методы `Ping` и `GetStudentByID`. Так проверяется, что сервер запущен, принимает запросы и возвращает данные студента.

8. **Что происходит, если клиент запрашивает несуществующего студента?**

   Сервер не находит студента в памяти и возвращает gRPC-ошибку со статусом `NotFound`. Клиент получает эту ошибку и может обработать её отдельно от успешного ответа.

9. **Почему для локальной учебной среды допустимо использовать insecure credentials?**

   В локальной учебной среде клиент и сервер запускаются на одном компьютере, поэтому для простого изучения gRPC можно не настраивать TLS. В production-среде такой вариант использовать нельзя, потому что соединение должно быть защищено.

10. **В каких случаях gRPC особенно удобен в backend-разработке?**

gRPC удобен для внутреннего взаимодействия между backend-сервисами, когда важны строгий контракт, типизация, быстрая сериализация и автоматическая генерация клиентского и серверного кода. Особенно это полезно в микросервисной архитектуре.
