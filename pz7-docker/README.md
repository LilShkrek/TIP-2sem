# Практическая работа №7

## Цель

Освоить контейнеризацию backend-приложения на Go с помощью Docker: подготовить Dockerfile, собрать Docker-образ, запустить контейнер и проверить работу сервиса.

## Задание

Реализован учебный сервис `tasks`, который запускает HTTP-сервер, читает порт из переменной окружения `TASKS_PORT` и отвечает на маршрут `GET /health`.

## Структура проекта

```text
pz7-docker/
├── services/
│   └── tasks/
│       ├── cmd/
│       │   └── tasks/
│       │       ├── main.go
│       │       └── main_test.go
│       ├── go.mod
│       ├── Dockerfile
│       └── .dockerignore
└── deploy/
    └── docker-compose.yml
```

## Локальный запуск

```bash
cd pz7-docker/services/tasks
go run ./cmd/tasks
```

По умолчанию сервис слушает порт `8082`. Порт можно изменить через переменную окружения:

```bash
TASKS_PORT=8090 go run ./cmd/tasks
```

## Сборка Docker-образа

```bash
cd pz7-docker/services/tasks
docker build -t techip-tasks:0.1 .
```

## Запуск контейнера

```bash
docker run --rm -p 8082:8082 -e TASKS_PORT=8082 techip-tasks:0.1
```

## Запуск через Docker Compose

```bash
cd pz7-docker/deploy
docker compose up -d --build
```

Остановка:

```bash
docker compose down
```

## Ответы на контрольные вопросы

1. **Чем Docker-образ отличается от контейнера?**

   Docker-образ — это шаблон, по которому создаётся контейнер. В образе описано, какая базовая система используется, какие файлы скопированы, какие команды выполнены при сборке и что нужно запускать при старте.  
   Контейнер — это уже запущенный экземпляр образа.

2. **Зачем нужен Dockerfile?**

   `Dockerfile` нужен для описания процесса сборки Docker-образа. В нём указывается базовый образ, рабочая директория, копирование файлов, установка зависимостей, сборка приложения и команда запуска контейнера.

3. **Что такое multi-stage build?**

   Multi-stage build — это подход, при котором сборка образа разбивается на несколько стадий. Например, на первой стадии Go-приложение компилируется, а на второй стадии в итоговый образ копируется только готовый бинарный файл.

4. **Почему для Go-сервисов удобно использовать multi-stage build?**

   Go-сервис обычно можно скомпилировать в один бинарный файл. Поэтому удобно собрать приложение в образе с Go SDK, а запускать уже в более лёгком runtime-образе. Это уменьшает размер итогового образа и убирает из него лишние файлы сборки.

5. **Зачем нужен `.dockerignore`?**

   `.dockerignore` нужен, чтобы исключить лишние файлы из build context. Например, в образ не должны попадать `.git`, временные файлы, логи, IDE-файлы, `.env` и локальные сборки. Это ускоряет сборку и делает образ аккуратнее.

6. **Для чего используются переменные окружения в контейнере?**

   Переменные окружения используются для передачи конфигурации в контейнер без изменения кода и пересборки образа. Например, в этой работе порт сервиса передаётся через переменную `TASKS_PORT`.

7. **Что делает флаг `-p` при запуске контейнера?**

   Флаг `-p` пробрасывает порт с хостовой машины внутрь контейнера. Например, `-p 8082:8082` означает, что запросы на порт `8082` хоста будут перенаправлены на порт `8082` внутри контейнера.

8. **Для чего нужен Docker Compose?**

   Docker Compose нужен для описания и запуска контейнеров через YAML-файл. Он позволяет не писать длинные команды `docker run`, а хранить параметры запуска, порты, переменные окружения и зависимости сервисов в одном файле.

9. **Почему контейнеризация упрощает деплой?**

   Контейнеризация делает запуск приложения более предсказуемым. Если Docker-образ собран правильно, его можно одинаково запускать локально, в CI, на VPS или в Kubernetes. Это снижает риск проблем из-за различий окружения.

10. **Почему не стоит вшивать конфигурацию и секреты прямо в образ?**

    Если вшить конфигурацию или секреты прямо в образ, для каждого изменения придётся пересобирать образ, а секретные данные могут попасть в репозиторий или registry. Правильнее передавать такие значения через переменные окружения, secrets или внешние конфигурационные механизмы.
